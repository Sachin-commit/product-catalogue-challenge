# Plan / spec

This is the plan that was agreed before any code was written. It was produced with Claude from the
challenge brief, reviewed, and approved with one decision (client = iOS). Deviations made during the
build are noted inline as **Changed:**.

## 1. Stack choice

- **Backend:** Node.js + TypeScript (the brief's preferred option).
- **Client:** iOS, SwiftUI. Chosen because it is the strongest stack of the person who has to defend
  and live-edit this code. React was the lower-friction option for reviewers; the trade-off is that
  reviewers need Xcode, which the brief explicitly allows.

## 2. Architecture

```
iOS app ──HTTP──▶ Node API (/api/v1) ──▶ ProductRepository port ──▶ Fake Store adapter (API or snapshot)
                                    ├──▶ MerchandisingSource port ─▶ merchandising.json (curated picks)
                                    └──▶ EmailSender port ─────────▶ SMTP adapter ──▶ Mailpit (local inbox)
```

The brief names three things that will change. Each one sits behind a seam:

| Will change | Seam |
|---|---|
| Product data source | `ProductRepository` interface; Fake Store shapes never leave the adapter |
| Email provider | `EmailSender` interface; SMTP adapter works with Mailpit locally and SES SMTP in prod |
| Look and feel | iOS `Theme` design tokens; views never hard-code colours or fonts |

Domain details: string product ids, prices as integer minor units + currency, category slugs generated
by the backend (Fake Store's names contain spaces and apostrophes).

## 3. Backend

Express 5, zod, pino, Vitest + supertest.

| Endpoint | Purpose |
|---|---|
| `GET /api/v1/featured` | The 5 curated "top rated" products |
| `GET /api/v1/categories` | Category list |
| `GET /api/v1/categories/:slug/products` | `{ category, topRated, more }` |
| `GET /api/v1/products?search=` | Server-side search (Fake Store has none) |
| `GET /api/v1/products/:id` | Product details |
| `POST /api/v1/enquiries` | 202 with an enquiry reference |
| `GET /health` | Liveness |

Fake Store handling: whole catalogue cached in memory with a TTL; empty-body 200s treated as failures;
upstream failures become a clean 502.

**Changed:** added `GET /api/v1/products/:id/image` so product images also go through the backend.

Security basics: zod validation on all input, helmet, JSON body limit, rate limit on enquiries,
no line breaks in email headers, Reply-To = customer, PII masked in logs, one error shape, secrets only via env.

**Changed:** added a `fakestore-snapshot` product source. The agent's sandbox could not reach
fakestoreapi.com, and an offline mode is useful for demos anyway.

## 4. iOS

SwiftUI, iOS 17+, Swift 6 language mode, no third-party dependencies. MVVM with `@MainActor @Observable`
view models depending on a `CatalogueAPI` protocol; `NavigationStack` with typed routes.
Screens: Home (featured + categories + search), Category (top rated + more), Search results,
Product details, Enquiry form sheet → Thank-you. Every screen has loading, empty and error states.
Base URL from an `.xcconfig`; `NSAllowsLocalNetworking` instead of disabling ATS. Project generated by
XcodeGen from `project.yml`, generated `.xcodeproj` committed.

**Changed:** UI rebuilt in UIKit (programmatic, coordinator, diffable data sources) instead of SwiftUI, at the
owner's request after the first version ran. View models, networking and tests were unchanged.

**Changed:** dropped XcodeGen. Xcode 16 synchronized folders mean new files need no project edits, which was
the reason for XcodeGen, without an extra tool. Client tests inject a transport closure instead of
`URLProtocol` stubs (no global state, safe for Swift Testing's parallel runs).

**Changed:** the plan assumed the agent could run `xcodebuild` on the linked Mac. It can only reach files
there, so the iOS build/run checkpoint is done by hand in Xcode, and CI runs the iOS tests on a macOS runner.

## 6. Testing

Backend: unit tests for search, merchandising selection, Fake Store mapping (incl. empty body),
caching, enquiry validation/composition, config; supertest for every endpoint's happy path and main failures.
iOS: Swift Testing for view-model state transitions and enquiry form validation; API client decoding
against JSON fixtures with a stubbed `URLProtocol`.
CI: GitHub Actions — backend check on Linux, Docker image build, iOS build + test on macOS.

## 7. Build order

1. Scaffold: agent instructions, plan, env example, docker compose (API + Mailpit)
2. Backend domain, ports, Fake Store adapter + tests
3. Catalogue endpoints + tests — checkpoint
4. Enquiry flow + email adapter + tests
5. iOS shell: networking, design system, config
6. iOS features in acceptance-criteria order + tests — checkpoint (run in Simulator)
7. CI
8. README, DECISIONS, AI_USAGE, PR description, final review
